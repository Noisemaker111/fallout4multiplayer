# FW_MINIMAL - modules compiled OUT of a minimal build.
#
# Purpose: the 1.10.163 port has to re-derive every version-pinned address by
# hand. Most of them belong to subsystems that are not needed to walk around a
# map and see another player move. Dropping those modules from the build drops
# their addresses from the port work-list, which is the whole point -- see
# docs/START_HERE.md section 4 and step A of section 5.
#
# This file is the SINGLE SOURCE OF TRUTH for the reduced set. It is read by:
#   * fw_native/CMakeLists.txt       - drops <stem>.cpp from the target
#   * tools/port_assess.py --minimal - drops <stem>.cpp AND <stem>.h from the
#                                      address scan, so the work-list count
#                                      matches what actually gets compiled
#
# Format: one module stem per line, relative to fw_native/src, no extension.
# Blank lines and whole-line "#" comments are ignored; a trailing comment on a
# stem line is NOT stripped. A stem covers both .cpp and .h.
#
# KEEP THIS FILE PURE ASCII. CMake's file(STRINGS) behaves like strings(1): it
# splits a line at the first non-ASCII byte, so an em dash inside a comment
# turns one comment into two "lines", the second of which no longer starts with
# "#" and gets parsed as a module stem.
#
# Adding a stem here is not enough on its own: if a module that STAYS includes
# the excluded header, that header needs an "#if FW_MINIMAL" stub block (see
# hooks/npc_ai_suppress.h for the pattern). Modules only reached from
# hooks/install_all.cpp need no stub -- the include and the install call are
# guarded there directly.
